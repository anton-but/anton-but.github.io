# Сайт-визитка — Антон Бут

Одностраничный статический сайт (без сборки, без зависимостей). Открывается двойным
кликом по `index.html` и одинаково работает как локально, так и на GitHub Pages.

## Структура файлов

```
antonbout-site/
├── index.html          # вся разметка и контент сайта (одна страница)
├── styles.css          # все стили: палитра, типографика, сетки, адаптив
├── script.js           # fade-up при скролле + подсветка активной секции в меню
├── favicon.svg         # иконка сайта (монограмма «АБ»)
├── .nojekyll           # пустой файл: отключает Jekyll на GitHub Pages
├── README.md           # этот файл
├── CONTENT-SPEC.md     # исходная контент-спека (справочно, на сайт не влияет)
└── assets/
    ├── portrait-hero.jpg      # портрет в hero-блоке
    ├── portrait-about.jpg     # портрет в блоке «Подход»
    ├── portrait-contact.jpg   # портрет в блоке «Связаться»
    ├── award-2024.jpg         # фото награждения, блок «Награды»
    └── anton-bout-cv.pdf      # резюме, кнопка «Скачать резюме (PDF)»
```

Секции идут в порядке: Hero → Масштаб → Подход → Компетенции → Избранные результаты →
Опыт → Награды → Образование и преподавание → Связаться (футер).

## Как отредактировать текст

Весь текст лежит прямо в `index.html` — никаких шаблонов и генераторов нет.
Откройте файл в любом редакторе (VS Code, Sublime, Notepad++) и правьте текст между тегами.

Ориентиры по блокам — HTML-комментарии вида `<!-- ОПЫТ -->`:

- **Hero** — блок `<section class="hero">`: имя (`<h1>`), роль (`.eyebrow`), ключевая строка
  (`.hero-lead`), теги (`<ul class="tags">`).
- **Масштаб (KPI)** — `<section id="scale">`: каждая цифра — `<p class="kpi-num">`,
  подпись под ней — `<p class="kpi-label">`. Сноска — `<p class="footnote">`.
- **Подход** — `<section id="approach">`: два абзаца текста.
- **Компетенции** — `<section id="skills">`: список `<li>`; нумерация 01, 02, 03…
  считается автоматически средствами CSS, вручную ничего писать не нужно.
- **Избранные результаты** — `<section id="results">`: каждая карточка — `<article class="result">`
  с цифрой (`.result-num`) и текстом (`.result-text`).
- **Опыт** — `<section id="experience">`: каждая позиция — `<li class="tl-item">`:
  период (`.tl-period`), должность (`.tl-role`), компания (`.tl-company`),
  строка контекста (`.tl-context`), достижения (`<ul class="tl-list">`).
  Чтобы добавить позицию, скопируйте целиком любой блок `<li class="tl-item">…</li>`
  и замените внутри текст. Точка и линия таймлайна рисуются автоматически.
- **Награды** — `<section id="awards">`: пары `<dt>` (награда) / `<dd>` (описание).
- **Образование и преподавание** — `<section id="education">`: пары `<dt>` / `<dd>`.
- **Связаться** — `<footer id="contact">`: email, телефон, Telegram, LinkedIn.

## Как заменить фото и резюме

1. Подготовьте новый файл и **назовите его так же**, как старый
   (`portrait-hero.jpg`, `portrait-about.jpg`, `portrait-contact.jpg`, `award-2024.jpg`,
   `anton-bout-cv.pdf`), затем просто положите его в папку `assets/` с заменой —
   тогда править HTML не придётся.
2. Если пропорции нового снимка сильно отличаются, поправьте `width` и `height` у
   соответствующего `<img>` в `index.html` (это только подсказка браузеру о пропорциях,
   реальный размер задаёт CSS) и при необходимости `object-position` в `styles.css`
   (например, `.hero-figure img{object-position:50% 22%}` — сдвиг видимой области кадра).
3. Рекомендации: hero — горизонтальный кадр ~1600×1200, портреты в «Награды» и
   «Связаться» — вертикальные ~1100×1650. JPG, качество 80–85, до ~300 КБ на файл.
4. Меняете имя файла — обновите путь в `<img src="./assets/…">`, `alt` к нему,
   а для hero — ещё и `<link rel="preload">` и `og:image` в `<head>`.

Все пути в проекте **относительные** (`./assets/…`), поэтому сайт работает
и в корне домена, и на подпути вида `username.github.io/antonbout-site/`.

## Как задеплоить на GitHub Pages

1. Создайте на GitHub пустой репозиторий, например `antonbout-site` (публичный).
2. В папке проекта выполните:

   ```bash
   git init                      # если репозиторий ещё не инициализирован
   git add .
   git commit -m "Сайт-визитка"
   git branch -M main
   git remote add origin https://github.com/USERNAME/antonbout-site.git
   git push -u origin main
   ```

3. В репозитории откройте **Settings → Pages**.
4. В разделе **Build and deployment**: Source — `Deploy from a branch`,
   Branch — `main`, папка — `/ (root)`. Нажмите **Save**.
5. Через 1–2 минуты сайт будет доступен по адресу
   `https://USERNAME.github.io/antonbout-site/`.

Файл `.nojekyll` в корне обязателен: он отключает обработку Jekyll,
чтобы GitHub Pages отдавал файлы как есть.

### Обновление после правок

```bash
git add .
git commit -m "Правки текста"
git push
```

GitHub Pages пересоберёт сайт автоматически. Если изменения не видны — обновите
страницу с очисткой кеша (Ctrl+Shift+R / Cmd+Shift+R).

### Свой домен (необязательно)

В **Settings → Pages → Custom domain** укажите домен, добавьте у регистратора
CNAME-запись на `USERNAME.github.io` и включите **Enforce HTTPS**.

## Технические детали

- Шрифты подключаются с Google Fonts: **Playfair Display** (заголовки) и **Inter** (текст) —
  оба с полной поддержкой кириллицы.
- Анимация появления блоков — `IntersectionObserver`; при системной настройке
  «уменьшить движение» (`prefers-reduced-motion`) анимация отключается.
- Семантическая разметка, один `<h1>`, `alt` у всех изображений,
  стили фокуса для навигации с клавиатуры, контраст по WCAG AA.
